# ADR-0001: Структура проєкту і технологічний стек

- Статус: Прийнято
- Дата: 2026-11-06

## Контекст
PayFlow одночасно є експериментальною платформою для магістерської роботи і проєктом для підготовки до співбесід.
До попереднього захисту близько двох тижнів, тому середовище має швидко розгортатися і бути відтворюваним.

## Рішення
- **Java 21 (LTS)**, **Spring Boot 3.5.x** (остання стабільна гілка 3.x), multi-module збірка **Maven** з Maven Wrapper.
- Кожен мікросервіс — окремий Maven-модуль (`wallet-service`, `transaction-service`). Спільний код виносимо лише тоді,
  коли він справді потрібен (наприклад, контракти подій), щоб сервіси випадково не зв'язувалися між собою.
- **Database-per-service**: в одному інстансі PostgreSQL окремі логічні бази даних (`wallet_db`, `transaction_db`).
  Жоден сервіс не читає таблиці іншого. Один фізичний інстанс робить локальний стек легшим: це спрощення
  середовища, а не архітектури.
- Схемою БД керує **Flyway**. Hibernate працює з `ddl-auto=validate`, тому розбіжність між сутностями і міграціями
  виявляється вже під час старту.
- **Оптимістичне блокування** (`@Version`) на гаманцях захищає від втрачених оновлень (lost update) при конкурентних переказах.
- **Тестування**: `*Test` — юніт-тести (Surefire), `*IT` — інтеграційні тести проти справжнього PostgreSQL
  у Testcontainers з `@ServiceConnection` (Failsafe, `mvn verify`).
- **Спостережуваність**: Actuator, Micrometer і Prometheus-ендпоінт з гістограмами затримок; Grafana бере дані з Prometheus.
- **Kafka** працює в режимі KRaft (без ZooKeeper). Автостворення топіків вимкнене, тому топіки оголошуються явно.

## Наслідки
- Для інтеграційних тестів потрібен запущений Docker.
- Бази обох сервісів спільно використовують один інстанс PostgreSQL, тож його відмова зачіпає обидва сервіси одночасно.
  Chaos-експерименти мають відключати окремі *сервіси*, або ж це розділення доведеться переглянути.
